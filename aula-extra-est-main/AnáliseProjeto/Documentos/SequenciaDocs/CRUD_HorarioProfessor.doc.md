# CRUD Horario do Professor

## Visao Geral
- Professor cria/edita/remove `schedule_blocks` e `block_parts` para definir disponibilidade.

## Diagrama de Sequencia
- Ficheiro: `DiagramasSequencia/CRUD_HorarioProfessor.md`

## APIs Envolvidas
- POST `/api/professors/{id}/schedule-blocks`
- PUT `/api/schedule-blocks/{id}`
- DELETE `/api/schedule-blocks/{id}`

## Tabelas Necessarias
- `schedule_blocks`, `block_parts`, `days`, `professors`

## SQL (Postgres) – Tabelas
> Definicoes completas em `sql/postgres/schema_all.sql`. Extractos principais:

```sql
CREATE TABLE IF NOT EXISTS schedule_blocks (
  id_schedule_block INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_professor INTEGER NOT NULL REFERENCES professors(id_professor) ON DELETE CASCADE,
  id_day INTEGER REFERENCES days(id_day),
  start_time TIMESTAMP,
  end_time TIMESTAMP,
  default_duration_minutes INTEGER,
  is_available BOOLEAN,
  recurrence_rule TEXT,
  created_at TIMESTAMP DEFAULT now(),
  updated_at TIMESTAMP DEFAULT now()
);

CREATE TABLE IF NOT EXISTS block_parts (
  id_block_part INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  id_schedule_block INTEGER NOT NULL REFERENCES schedule_blocks(id_schedule_block) ON DELETE CASCADE,
  start_offset_minutes INTEGER,
  end_offset_minutes INTEGER,
  is_available BOOLEAN
);
```

## Validacoes e Regras
- `end_time` > `start_time` no bloco.
- Fragmentos nao devem ultrapassar os limites do bloco.
